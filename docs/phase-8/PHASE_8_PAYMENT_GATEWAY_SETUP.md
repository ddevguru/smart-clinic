## Razorpay Integration, Security Architecture & Order Lifecycle

## 1. Overview & Security Principles

Smart Clinic OS integrates **Razorpay** to process SaaS subscription fees in Indian Rupees (INR).

### Core Security Rules
1. **Zero Client Trust on Pricing:** The client *never* specifies the charge amount. The client sends `{ plan_id, billing_interval }`. The backend looks up the plan from `subscription_plans`, computes 18% GST, and invokes Razorpay API.
2. **Server-Side Cryptographic Verification:** Subscriptions are activated *only* after validating the HMAC-SHA256 signature generated with the secret key.
3. **Double Verification via Webhooks:** If the user closes their browser before the redirect completes, the Razorpay webhook handles authoritative activation idempotently.

## 3. Cryptographic Signature Verification

Razorpay payment signature is generated by the gateway as:
$$\text{Signature} = \text{HMAC-SHA256}(\text{order\_id} + "|" + \text{payment\_id},\, \text{key\_secret})$$

### Backend Verification Implementation (`razorpayService.js`):
```javascript
static verifyPaymentSignature({ order_id, payment_id, signature }) {
  if (!order_id || !payment_id || !signature) return false;

  const secret = this.getKeySecret();
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(`${order_id}|${payment_id}`)
    .digest('hex');

  try {
    const sigBuf = Buffer.from(signature);
    const expBuf = Buffer.from(expectedSignature);
    if (sigBuf.length === expBuf.length && crypto.timingSafeEqual(sigBuf, expBuf)) {
      return true;
    }
  } catch {
    return false;
  }
  return false;
}
```
